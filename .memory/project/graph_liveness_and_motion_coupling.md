# Graph liveness and motion-coupling invariants

- A pose graph that reports `nfev=1`, `cost=0`, zero residuals, and zero target-frame support is a pass-through, not an optimized physical state. Treat its variables as untested inputs until factor support, active residual counts, input-output deltas, and gauge/covariance are recorded per factor family.
- On clip001850 the P15 rigid pose graph is inert by construction, not because variables are unwired. `solve_v19_rigid_object_pose_graph.py` optimizes correction deltas around raw direct ICP fits. Its anchor/temporal/acceleration terms are homogeneous in the correction field, and the only nonzero driver would be a nonpenetration target. The run has `constraint_report=null`, and the available P16 constraint state has zero accepted correction rows because the keyboard mesh is non-watertight. Therefore `x0=0` is the global optimum and the 13 direct ICP poses pass through unchanged.
- The clip001850 keyboard pose state has three simultaneous failure mechanisms: 65 frames have no visible metric surface (`missing_initial_graph_pose`); 72 frames have visible surface but fail rigid-fit eligibility from SAM2 hand/background leakage; and the graph is a zero-delta corrector, not a physical trajectory estimator. Nearest-hold rows collapse to two poses, not one: f0-29 hold the f30 pose, while f78-149 hold the f77 outlier pose about 180 mm away from the rest cluster.
- Do not repair a static keyboard by trajectory smoothing or by writing a rest-cluster statistic into missing-frame pose rows. The direct fits form a rest-pose cluster plus outliers/mask drift; a pose-acceleration prior connects those outliers into a fabricated slide, while a hard static fill launders a diagnostic reference into pose state. The correct order is regime classification (static vs moving vs mask drift), outlier rejection, support recovery on leaked masks when possible, then null-pose `unknown` rows for frames without admissible observations unless a live solver later produces explicit `solver_estimate` rows with posterior covariance.
- Anchor frames require pose-independent regime validation. In clip001850, the visible-geometry anchor f75 has extent ratio 1.0 only because it is compared to itself, but its centroid is 199.5 mm from the static rest cluster. Any eligibility gate, canonical mesh, or ICP seed derived from such an anchor contaminates downstream pose rows. Re-anchor static objects to the rest consensus, not to a self-consistent but drifted frame.
- A delaminated mask is not recoverable by geometric quarantine. For clip001850 f78-149, hand/depth-cleaned mask centroids remain 138-278 mm from the observed rest cluster and 0/72 frames recover consensus support. The honest state is `mask_unreliable` with null object pose, unless a new perception pass or a live solver with explicit evidence produces a posterior estimate. A rest-cluster reference may reject outliers; it must not become missing-frame pose, factor prior, contact evidence, or render-localized body.
- Pose provenance audits must cover the whole advertised render surface, not only the nominal `render_artifacts` pointer. The clip001850 correction initially left P15-bodied `full_duration_render` and `generic_contact_state_render` root-manifest blocks with green gates; both drew a localized body on 142 unknown frames despite the current pose table being pure. A package is clean only when every current/advised render manifest either consumes the current pose-observation table or is structurally demoted as superseded negative evidence, and render-consumption rows record that status. Superseded bad renders may remain as negative evidence, but current render-surface violations must be zero.
- Object motion coupling is admissible contact evidence only when the object trajectory is live and de-noised. On clip001850, the motion-coupling channel is negative: f36 has strongest fingertip approach but only 8.6 mm keyboard response, below the direct-edge median; f46 is the largest window edge but occurs during hand withdrawal and mask re-acquisition. Motion coupling cannot promote contact under those conditions.
- `confirmed_contact` requires floor-independent provenance: motion-coupling onset from a live trajectory or GT. Signed distance, shrunken gaps, hand-depth shifts, smoothed pose rows, or agent interaction labels do not populate that provenance.
- The next HOT3D R2 slice after clip001850 cleanup is clip001851 keyboard correspondence-first object pose, with clip001849 as lower-motion rigidity control. The reason is mechanism-level: clip001851 has persistent visible surface and a live 3D translation signal (component-wise GT range `[152.6, 194.5, 109.2]` mm; 270.3 mm diagonal), while the documented depth-ICP baseline leaves a 38.85 mm residual that stationary repair worsens. R2 prediction must still be GT-clean: raw pinhole frames, prediction SAM2 masks, prediction metric depth, and prediction camera annotations may enter the runtime; HOT3D GT object pose/hands/masks/proximity labels are scoring-only after prediction freeze.
- CoTracker tracks must be lifted in the same pixel coordinate frame as the metric depth and intrinsics. For HOT3D pinhole runs, the manifest RGB/mask frames can be 960x960 while UniDepth/source intrinsics and visible-geometry annotations are 1408x1408. `tracks_xy` from CoTracker are manifest-image pixels; they must be scaled to `tracks_depth_xy` before depth sampling and world lifting. Failing to scale creates meter-scale false world points while the overlay still looks attached, so sparse visible-sample gating is the necessary detector. On clip001851, scaling plus visible-surfel query masks changed sparse support from 0 usable tracks / 0 edges / 1.12 m median nearest-sample distance to 52 usable tracks / 3,598 edges / 2.14 mm median nearest-sample distance and 147/149 rigid-ready adjacent pairs, without using GT.
- A visible-surface patch SE(3) trajectory from CoTracker is a correspondence diagnostic until a valid gauge and admissible absolute geometry backbone exist. A local near-field rigid patch can be a useful confound bound, but subtracting its own best-fit SE(3) only proves that patch is rigid; it does not prove the patch is static or that the SE(3) is camera/extrinsic drift. Completed-mesh ICP is not an admissible absolute pose backbone for research R4 after the clip001850 phantom-geometry finding; use observed-surface/visible-surfel geometry or keep the pose as relative/diagnostic. Gauge-uncovered frames remain unknown/unverified, with no identity-gauge fallback, smoothing, or interpolation.
