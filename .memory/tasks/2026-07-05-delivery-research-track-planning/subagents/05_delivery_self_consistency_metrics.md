Core rule: the useful GT-free metric is a disagreement between two measurement paths for the same physical or semantic claim. Use the metrics to route reruns/tuning and assign confidence tiers; do not use them as arbitrary stop gates that suppress approximate outputs.

Current boundary: hand accuracy has a real public-GT validation path on HOT3D. Head/camera accuracy currently has strong GT-free consistency/drift metrics, but a true 5 mm head/camera accuracy claim requires a camera-GT/fiducial/IMU validation set or exposed public camera trajectory sidecar.

## Metric set

### A. Head/camera accuracy and drift

| Metric name | Mechanism | Computation inputs | Expected scale / threshold | Known blind spots | Rerun / tuning trigger | Dataset / clip to validate |
|---|---|---|---|---|---|---|
| **HC1. Static-scene camera reprojection residual** | A correct head/camera trajectory should reproject static scene points consistently across frames after masking moving hands/objects. Dynamic background or bad masks can look like camera drift. If residual grows after scene cuts, split trajectory into semantic clips before SLAM. | `trash_1050` validates failure detection because the world was drift-bent; `task5_tomato_960` and `window_putty_knife` provide tabletop/static-scene sanity checks. Report absolute trajectory error, relative pose error, and rotation error. | Delivery target: median translation <=5 mm, p90 <=10 mm on near manipulation intervals; rotation target should be stated in deg and converted to near-field pixel/mm impact. | Not currently proven by the requested files. If GT ATE passes but rendered hands drift, route to hand/intrinsics. | HOT3D clips `001849/001850/001851` only if camera/head GT sidecars are available; otherwise add a short fiducial/tabletop camera-GT validation clip before making a 5 mm head/camera claim. |

### B. Hand accuracy

| Metric name | Mechanism | Computation inputs | Expected scale / threshold | Known blind spots | Rerun / tuning trigger | Dataset / clip to validate |
|---|---|---|---|---|---|---|
| **H1. Public-GT wrist/root translation error** | Camera-frame wrist/root error directly measures 3D hand position without object/contact confounds. This is the clean separated hand-accuracy metric. | Predicted MANO wrist/root per hand/frame, HOT3D MANO GT, side/frame matching, fixed camera-frame convention, no trajectory alignment unless explicitly declared. | Stakeholder target: median <=5 mm; yellow 5–10 mm; red >10 mm. Current demo result under disclosed even/odd per-clip GT calibration: `001849` 5.1/6.2, `001850` 6.5/7.6, `001851` 4.7/7.3 mm. Uncalibrated reference remains 15.5–35.9 mm. | Current sub-10 result uses GT-fitted per-clip calibration, so it proves smooth correctability, not deployable GT-free calibration. Wrist can be good while fingers/articulation are wrong. | Smooth bias over time -> camera/registration self-calibration target. Per-frame noisy residual -> hand estimator/fusion. Side-specific residual -> per-side detection/crop/label issue. | HOT3D clips `001849`, `001850`, `001851` with existing evaluator and ledger. |
| **H2. Visible-joint MPJPE / root-relative geometry error** | Separates visible MANO shape/articulation quality from wrist translation. WiLoR-visible geometry + HaWoR wrist improved visible-joint MPJPE on held-out clips, showing a real geometry mechanism. | Predicted 21 MANO joints, HOT3D GT joints, visibility/modelled-hand mask if available, same camera convention. | Use as secondary target. Current held-out evidence: WiLoR-visible geometry + HaWoR wrist improves MPJPE 47.2->33.0 on `001850` and 46.7->36.9 on `001851`; root/wrist unchanged by construction. Red if geometry worsens while wrist improves. | Evaluator lacks per-joint visibility masks in current table; occluded fingers can dominate. Root-relative MPJPE can improve while whole hand is misplaced. | If H1 passes and H2 fails, tune articulation/geometry source, not camera. If both fail similarly, tune camera/translation. | HOT3D `001850/001851` held-out clips; `origami_paper` validates occlusion-driven joint-label relabel behavior visually. |
| **H3. Hand reprojection residual to independent 2D evidence** | A metric 3D hand should project onto visible 2D hand keypoints. This catches image-space drift in final rendered annotations. | Final hand state, intrinsics, independent 2D keypoints/detector tracks, per-frame visibility/provenance. Report median/p95 px per side and accepted-frame count. | QC chip thresholds already used: high <=10 px median, medium <=20 px, low/review >20 px or inferred/fallback provenance. Red: median >20 px or residual burst >50 px for >=3 consecutive detected frames. Current good medians: tomato 6.5/4.2 px, trash 10.4/7.3, phone 8.4/13.7, window 5.4/3.7, scissors 4.3/12.6; origami-left 18.4 is review-tier. | 2D-consistent but wrong-depth hands pass. Detector can be wrong under occlusion or swapped labels. | If H3 fails in a band, rerun visible detector/refit or apply band-local source escalation; do not globally reweight the whole clip. If H3 passes but size/depth fails, route to H5. | All six demo clips; `trash_1050` track v3c validates band-local escalation; `origami_paper` validates joint-label relabel under occlusion. |
| **H4. Cross-detector keypoint residual** | Independent 2D detectors disagree when one hand stream is wrong; this detects bad visible hand localization before any 3D solver. | Primary hand projection/keypoints, independent detector such as rtmlib, side association, visibility mask. Report median/p95 px and flagged frames. | Green initial band: median <=25–30 px and p95 not dominated by bursts; red: median >50 px or p95 >150 px. Proven decisive: trash left median 283.8 px / p95 760.9 px flagged a superseded bad hand layer. | Cannot see depth error. Can fail when both detectors see different occluded hands or labels. | Large residual -> rerun hand detection/source selection before trusting 3D state; if only p95 bursts, use targeted frame review/source hysteresis. | `trash_1050` validates failure; tomato/phone/window validate low-residual states. |
| **H5. Projected-size vs detected-size consistency** | Rendered hand bbox size compared with detected hand bbox measures relative depth/scale error: if the projection is too small, the 3D hand is too deep or intrinsics/crop scale is wrong. | Projected MANO bbox height/area, detector hand bbox/mask, intrinsics, visibility state. Report ratio `projected_size / detected_size` and implied depth ratio. | Green: 0.9–1.1. Warning: outside 0.85–1.15. Red: >20% scale/depth error. Proven blind-spot closer: trash f231 had 117 px projected vs ~150 px detected, ~22% too deep, while 2D keypoint residual was only 38 px. | Detector box changes with finger spread/occlusion. Foreshortened palms can mimic depth error. | If H3 passes but H5 fails, rerun/tune depth, crop-scale, or intrinsics adapter; do not claim 3D accuracy from 2D agreement. | `trash_1050` f231 validates; all demo clips can emit this cheaply. |
| **H6. Hand temporal jitter / relative-motion coherence** | A temporally coherent hand state should move smoothly except where the source video shows fast motion. Per-frame independent fits produce visible jitter; HaWoR relative motion is sometimes reliable but can also contain discontinuities. | Wrist translations, root orientations or MANO vertex-cloud rigid transforms, frame rate, optical-flow/2D wrist motion for normalization, provenance/source switches. Report median/p95 mm/frame and deg/frame, plus residual to image motion if available. | Use as review index, not hard physical gate. Existing medians range ~2–28 mm/frame; p95 >50 mm/frame or angular p95 >15 deg/frame on slow clips should trigger review. Red: discontinuities of meters/frame or source-switch spikes. | Fast real motion produces high displacement. Over-smoothing can pass while visibly lagging. HaWoR relative motion failed on trash with 7–11 m/frame discontinuities, so relative priors must be robustified. | If high only at source switches, add hysteresis/temporal fusion. If high while H3 worsens, rerun hand source. If low but H3 drifts, smoothing is hiding mislocalization. | Demo self-consistency table across tomato/trash/origami/phone/window/scissors; trash validates robust-delta cap need. |

### C. Visible drift, intrinsics, and reprojection diagnosis

| Metric name | Mechanism | Computation inputs | Expected scale / threshold | Known blind spots | Rerun / tuning trigger | Dataset / clip to validate |
|---|---|---|---|---|---|---|
| **R1. Rendered-overlay drift burst score** | User-visible drift is residual that persists in final render, not just in backing JSON. Track residual bursts where projected hands/objects move away from visible evidence. | Final render state, intrinsics, per-frame projected hand joints/meshes/object contours, independent 2D detectors/masks, optional rendered-video frame extraction. | Same hand residual bands as H3 for hands. For drift bursts: red when |projected-vs-detected| >50 px for >=3 consecutive detected frames or when residual has a monotone trend over >1 s. | Needs reliable detector/mask. Pure visual review may catch orientation/finger mistakes not visible in centroid residual. | Band-local hand/source rerun for localized bursts; intrinsics/camera rerun if all layers drift coherently; render wiring fix if backing state is good but video is wrong. | Tomato visible drift concern; `trash_1050` band 840–880 validates band-local escalation; `phone/window/scissors` validate current reduced recipe. |
| **R2. Intrinsics/crop-adapter residual-reduction sweep** | If a single focal/principal/crop/convention correction reduces residuals across hands, object masks, and static tracks, the root cause is camera adapter/intrinsics rather than hand noise. | Intrinsics, image resize/crop metadata, final 3D hand/object/static points, independent 2D keypoints/masks/features. Fit small bounded deltas to focal scale, principal point, and crop transform; compare residual before/after. | Healthy: best correction is tiny (<1–2% focal-scale, <5–10 px principal shift) and improves residual <10%. Red: >2–3% focal/crop shift or >25% residual improvement across independent layers. Translation-only hand refit floor: 7–10 px is normal in trash/egoscale regime; 23–26 px floor on close HOT3D hands indicated crop/weak-perspective mismatch. | A per-frame hand model bias can masquerade as intrinsics if only hand points are used. Object masks with wrong geometry can corrupt the fit. | If global correction helps all layers, patch/tune intrinsics/crop adapter and rerun projection. If only one layer improves, route to that source. If no correction helps, drift is likely temporal/state, not intrinsics. | HOT3D close-hand clips `001849–001851` validate high residual floor; trash/tomato/phone/window/scissors validate low-residual egoscale behavior. |
| **R3. Object/visible-surface silhouette IoU** | Projected object geometry or visible surface must overlap independent object segmentation. It catches wrong mesh, wrong scale, and fused scene slabs. | Object mesh/surface pose, intrinsics, per-frame object masks from SAM2/open-vocabulary tracking, sampled frames. | For rigid visible object geometry: IoU >0.5 is strong; 0.3–0.5 review; <0.2 means image-space claims must come from per-frame mask/visible surface, not fused body fill. Proven: tomato clean mesh ~0.50–0.55; wrong tomato mesh 0.08; trash fused geometry 0.184 median. | Deformable/transparent/thin objects have low IoU despite useful visible surface. Mask errors can punish good geometry. | Low IoU -> do not promote mesh fill as precise geometry; rerun segmentation/anchor selection/scale sweep. If hand drift is good but object IoU fails, separate object/render confidence from hand confidence. | Tomato validates mesh/scale selection; `trash_1050` validates low-IoU warning; phone/window/scissors validate visible-surface coverage. |
| **R4. Final-state/render provenance contradiction count** | Current detector/provenance must outrank stale upstream validity. A rendered solid/hidden/ghost state contradicting current evidence is a wiring bug, not model uncertainty. | Current hand/object provenance, visibility states, detector rows, final render/QC chips, per-frame state source ids. Count frames where current visible evidence is hidden/ghosted, or inferred/fallback state is rendered solid. | Threshold is zero for high-confidence delivery. Any contradiction is a fix-before-claim defect. | Requires source ids and render chips to be complete. It does not judge physical accuracy, only state/render consistency. | Fix dataflow/render gating; do not rerun model first. Rebuild dependent state if source artifacts changed. | `trash_1050` f850 validates stale-validity bug class; origami/phone QC variants validate current provenance chip behavior. |

### D. Semantic 2–3 s clip and caption quality

| Metric name | Mechanism | Computation inputs | Expected scale / threshold | Known blind spots | Rerun / tuning trigger | Dataset / clip to validate |
|---|---|---|---|---|---|---|
| **S1. Segment coverage and duration compliance** | The semantic product is a full-timeline partition into usable 2–3 s clips; gaps/overlaps or long mixed-action spans make captions unusable. | Raw video fps/duration, proposed segment start/end times, scene/action boundary metadata. | 100% timeline coverage, no overlaps, no dropped frames. >=90% of interior segments in 2–3 s; edge segments may be shorter. Red: any gap/overlap or many >4 s mixed-action segments. | A true atomic action can last longer than 3 s; enforcing duration alone can split semantics badly. | Rerun segmentation/windowing when duration compliance fails; if semantic change points disagree with duration, preserve semantic boundary and allow documented exception. | All six demo clips; phone tapping and window wiping are good short-action validation cases. |
| **S2. Caption entity/action grounding score** | Caption nouns and verbs should be supported by visible objects, hand motion, and VLM/frame evidence. Grounding prevents plausible but unsupported captions. | Caption text, object detector/SAM2 tracks, hand tracks, sampled frames, optional VLM yes/no verifier, extracted entities/actions. | For high-confidence semantic clips: every critical noun visible or explicitly absent/occluded; action supported by hand/object motion or >=2/3 VLM verifier agreement. Red: unsupported critical noun/action, internal case ids, non-ASCII glyph regressions, or caption contradicts visible frame. | VLM can agree on a common hallucination. Fine force/contact intent can be invisible. Object detectors may miss small tools. | Rerun captioning with object-plan constraints; rerun detector prompts when noun grounding fails; send low-score clips to human review or low-confidence tier. | Demo captions already manually checked: tomato, trash, origami, phone calculator, window putty knife, cut cloth scissors. Track R3 caption regression validates the internal-id/glyph failure mode. |
| **S3. Caption self-consensus under overlapping windows** | A robust caption should remain stable under neighboring 2–3 s windows and prompt variants, while genuinely changing near boundaries. | Multiple VLM/LLM captions per window, caption embeddings, extracted verb/noun tuples, overlap schedule. | Within-segment caption embedding similarity >=0.75 or >=2/3 same main verb+noun. Across proposed boundary, similarity should drop or action/entity tuple should change. Red: high disagreement inside segment or no change at boundary. | Consensus can preserve shared hallucinations. Embedding similarity can miss important verb differences. | If disagreement is high inside a segment, split or rerun VLM with constrained prompts. If no contrast at boundary, merge adjacent segments. | Six demo clips; especially phone tap/hold intervals, window wiping, scissors cutting, origami folding stages. |
| **S4. Boundary stability under resampling** | True semantic boundaries should not move far when sampling offset or window stride changes. | Segmenter outputs from offset grids (e.g., 0, 0.5, 1.0 s), VLM/window scores, raw timestamps. | Boundary standard deviation <=0.5 s is usable; >1.0 s indicates ambiguous or unstable boundary. | Gradual actions have inherently fuzzy boundaries; occlusion can hide action start/end. | If unstable, use lower confidence, merge segments, or request human boundary review; do not present precise 2–3 s clip labels. | Same-day clips (`phone_calculator`, `window_putty_knife`, `cut_cloth_scissors`) are best because their action changes are visually obvious. |
| **S5. Caption-to-annotation agreement** | Semantic captions should not contradict physical annotation fields: visible hand, object presence, occlusion, and contact/near-contact states. | Caption entities/actions, hand/object visibility states, contact/near-contact timeline if present, object masks, QC provenance. | High-confidence caption cannot name a manipulated visible object absent from masks/state, or claim touching/grasping when annotation says out-of-frame/unresolved throughout. | Annotation fields may be missing or uncertain; absence of HOI in delivery track means this is a consistency check, not a contact truth test. | Rerun object planning/SAM2 if caption entity has no track; downgrade caption if annotation is unresolved; route to research track if contact semantics are needed. | Tomato/trash QC clips for contact wording; phone/window/scissors for object-presence grounding without full HOI. |

## Routing rules for iteration

- **Head/camera metrics fail, hand image metrics pass:** tune camera/SLAM/intrinsics; do not rerun hand model first.
- **Hand reprojection fails while camera/static metrics pass:** rerun hand detection/refit/fusion for the affected band or side.
- **Hand reprojection passes but projected size fails:** tune depth/crop-scale/intrinsics; 2D agreement is not enough for 3D accuracy.
- **Intrinsics sweep improves all layers:** fix the adapter/camera convention and rerun projection; do not patch per-hand residuals.
- **Only one source band diverges:** use band-local escalation/source hysteresis; global reweighting already resurrected old garbage states in the demo sprint.
- **Caption grounding fails:** rerun semantic VLM with object-plan constraints or lower the semantic confidence; do not let fluent captions outrank visible evidence.
- **Throughput lane fails:** tune the over-budget lane directly. Current dominant measured blocker is full-rate SAM2, not hands.

## Residual risks

1. GT-free camera consistency cannot certify a 5 mm head/camera claim without camera GT, fiducials, or an equivalent absolute reference.
2. Current HOT3D sub-10 hand result proves smooth correctability under disclosed GT calibration; delivery still needs a GT-free self-calibration mechanism before claiming deployable 5 mm hand accuracy.
3. VLM semantic consensus can preserve a shared hallucination; semantic metrics need periodic human audit on stratified clips.
4. Throughput feasibility is conditional on SAM2 reduction/acceleration and measured HaWoR/camera keyframing; current full-rate SAM2 breaks the 5-node budget.
